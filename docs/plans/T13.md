## T13b plan (arena prep phase)

Author: claude-2. Implementer: codex-2. Base: main 5407ed8.

### Decisions
- **D1 Config:** new int key `arenaPrepSeconds`, default 30, range 0–300 in all modes. The value 0 means "no prep" (the old flow, where the first countdown number can be lost). A range with min. 0 lets tests and admins turn it off. No debug-only bound is necessary.
- **D2 New battle state `PREP`** between `WAITING_ARENA` and `COUNTDOWN`. It starts on the tick when the arena is ready (`onReady` places the players, as now). After `prepTicks`, the flow goes to `COUNTDOWN` for wave 1 and sends `Countdown(1, N)` on that tick. This is the same event as now, but `prepTicks` later. Thus the client has loaded the arena before the "3" comes (fixes the lost first "3").
- **D3 No elimination in `PREP`.** The flow does not check `allDown` or `anyOnline` in `PREP`. The checks start on the first tick after prep end, as in `COUNTDOWN` now.
- **D4 Deaths in `PREP`:** the normal arena respawn timer applies (`RespawnManager.allowDeath` already handles all states except `WAITING_ARENA`/`ELIMINATED`). At prep end, each online team player in the respawn timer respawns at once at the team spawn (`placeAtSpawn`, timer cancelled). Thus a death at 0:01 does not eliminate a 1-player team at countdown start.
- **D5 Rejoin in `PREP`:** `ArenaBattles.rejoin` puts the player at the team spawn with `placeAtSpawn` (no respawn timer). This is the same as `FINISHED`. Note: T13a (claude-1/codex-1) changes the rejoin path too. Expect a small merge conflict in `ArenaBattles.rejoin`.
- **D6 Time:** `elapsed` (team time, finish time, tiebreak data) does not count in `PREP`, as it does not count in `WAITING_ARENA` now. The wave max time (`waveMaxTimeSeconds`) starts when the wave spawns (`fightStart`, `stateTicks = 0` in `spawn`). Prep does not change it. `READY_TIMEOUT_TICKS` counts only `WAITING_ARENA`, so prep does not change it.
- **D7 Sudden death keeps its start (no prep).** Its script uses `prepTicks = 0`. Reason: the arenas are loaded, and the sudden death message and horn already mark the start. Remaining risk: players of an eliminated team watch the other arena and change dimension at sudden death start. They can lose the first "3" there. MANUAL-TEST has a check for this. If it fails, add a follow-up task (short fixed SD prep). Do not change it in T13b.
- **D8 HUD:** boss bar in `PREP`: `Get ready – 0:25` (`TimeFormat.mmss(left)`), progress `left / prepTicks`, the phase color (red). Title at prep start: `Get ready`, subtitle `Wave 1 in 30 s` (fade 0/40/10). The title can be lost while the client loads; the boss bar is the main display. Do not use the action bar (the respawn timer uses it).
- **D9 Sounds (T12g):** no new sound. The `COUNTDOWN` sounds and the `GO` sound start after prep, because they come from the same `Countdown`/`SpawnWave` events.

4. `arena/BattleScript`: new last component `int prepTicks` (`< 0` -> `IllegalArgumentException`). Keep a 5-argument constructor with `prepTicks = 0`, so that old unit tests and the sudden death script stay unchanged.
5. `arena/BattleEvent`: `record Prep(int secondsLeft)`. It is sent once on the ready tick when `prepTicks > 0`.
6. `arena/BattleFlow`:
   ```java
   public enum State { WAITING_ARENA, PREP, COUNTDOWN, FIGHT, COOLDOWN, FINISHED, ELIMINATED }
   // top of tick(): count elapsed/stateTicks only when state != WAITING_ARENA && state != PREP
   if (state == State.WAITING_ARENA) {
       if (!in.arenaReady()) return List.of();
       wave = 1;
       stateTicks = 0;
       if (script.prepTicks() > 0) { state = State.PREP; return List.of(new BattleEvent.Prep((script.prepTicks() + 19) / 20)); }
       state = State.COUNTDOWN;
       return List.of(new BattleEvent.Countdown(1, (script.countdownTicks() + 19) / 20));
   }
   if (state == State.PREP) {
       if (++stateTicks < script.prepTicks()) return List.of();
       state = State.COUNTDOWN;
       stateTicks = 0;
       return List.of(new BattleEvent.Countdown(1, (script.countdownTicks() + 19) / 20));
   }
   ```
   Add `int prepLeftTicks()` (0 outside `PREP`) and `void setPrepLeft(int ticks)` (only in `PREP`, clamp to `0..prepTicks`; 0 means countdown on the next tick). Check the old `countdownTicks == 0` case: the current ready path sends `Countdown(1, 0)` and spawns on the next tick. Keep this behavior after prep.
7. `arena/ArenaBattle`:
   - `tick()`: remember `wasPrep`. When the state changes from `PREP` to `COUNTDOWN`, call `onPrepEnd()`: respawn the online team players in the respawn timer at once (`placeAtSpawn`), then `group.respawns().cancelTeam(team)`.
   - `handle`: `case BattleEvent.Prep p` -> title from D8, no sound.
   - `hud()`: `case PREP` -> D8 line.
   - `running()` is already true in `PREP` (it excludes only `WAITING_ARENA`, `FINISHED`, `ELIMINATED`). Update the Javadoc ("prep, countdown, fight, cooldown"). `FullGameFixture.arenaReady()` uses `running()`, so it is also true in `PREP`.
   - Debug hook: `public int prepLeftTicks()` and `public void setPrepLeft(int ticks)` (delegate to the flow).
8. `arena/ArenaBattles.rejoin`: `case PREP -> battle.placeAtSpawn(player);` (D5).
9. `arena/ArenaPhaseListener.onEnter`: pass `config.arenaPrepSeconds() * 20` as `prepTicks`. `startSuddenDeath` passes 0 (D7).
10. `debug/DebugDriver.timer(seconds)`: in `ARENA`, if one or more battles are in `PREP`, set the prep time left of these battles to `seconds * 20` and return. Otherwise keep the current rejection ("The phase timer cannot control arena battles"). `DebugDriver.state()`: add `"prepLeft"` (ticks) to each battle object. The battle `"state"` field can now be `"PREP"`; tell the VM test author (findings scripts can read this field).
