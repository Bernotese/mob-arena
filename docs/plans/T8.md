# T8 – Results, sudden death, end (plan)

Read: SPEC 7.6, 8, 9; `docs/plans/T7.md` sections 1.4, 9. Package `dev.mobarena.result`. No mixin.
Config: read only `ctx.config()` (per-phase `MobArenaConfig.Snapshot`), e.g. `ctx.config().endScreenSeconds()`. Progress type: `core.TeamProgress(clearedWaves, killsInCurrentWave, ticks)`.

## 1. Classes
| Class | Kind | Job |
|---|---|---|
| `Outcome` | pure, sealed | `Running`, `Finished(long ticks)`, `Eliminated(TeamProgress p)`. |
| `Verdict` | pure, sealed | `Pending`, `Win(TeamId)`, `SuddenDeath`, `Draw`. |
| `WinResolver` | pure | `Verdict arena(Outcome red, Outcome blue)`, `Verdict suddenDeath(Outcome red, Outcome blue)`. Table in section 2. |
| `ResultTracker` | MC | Implements `ResultHooks` (put in ctx at `ARENA.onEnter`) and the T7 `BattleListener` (sudden death). Stores one `Outcome` per team. Sets `dirty`. |
| `ResultPhaseListener` | MC | At tick end, if `dirty`: run the resolver once. `Win`/`Draw` → store `ResultKeys.RESULT`, `GameManager.finish()`. `SuddenDeath` → `GameManager.enterSuddenDeath()`. |
| `SuddenDeath` | MC | `SUDDEN_DEATH` phase listener. Section 3. |
| `EndSequence` | MC | `END` phase listener. Section 4. |
| `ResultKeys` | MC | `Key<GameResult> RESULT`; `record GameResult(Optional<TeamId> winner, String reason)`. |

Same-tick rule: hooks only record. The resolver runs once per tick (`END_SERVER_TICK`). Thus two events in one tick give one verdict.

## 3. Sudden death flow
1. `ARENA.onExit` (T7) removes wave mobs. `SUDDEN_DEATH.onEnter`: new `ResultTracker` outcomes (both `Running`).
2. All team players: `SURVIVAL`, teleport to the own team spawn (eliminated players come back from the other arena), full health and food. Arenas are not repaired.
3. For each team: `ArenaBattle.startSuddenDeath(team, ctx, tracker)` (T7). One wave = all 3 enemy waves, countdown as normal, cooldown 0, max time `suddenDeathMaxTimeSeconds`, tag `n = 4`.
4. Tracker → resolver (`suddenDeath`) each dirty tick → `Win`/`Draw` → `GameManager.finish()`.
5. `SUDDEN_DEATH.onExit`: T7 stops the battles.

## 4. End sequence (`END`)
- `onEnter`: read `RESULT`. Title to all game players: `Team RED wins` (team color) or `Draw`; subtitle = reason (`All waves cleared`, `More progress`, `Sudden death`). Use T9 `Titles`.
- Fireworks: every 20 ticks for the first 5 s, one `FireworkRocketEntity(level, x, y, z, stack)` [V] above each online winner player (stack with `DataComponents.FIREWORKS`, team color). Draw: no fireworks.
- Chat summary: per team cleared waves, kills, time (`m:ss`).
- After `endScreenSeconds` (phase timer): `GameManager.endPhaseNow()` → `LOBBY`.
- `onExit`: clear inventories of all game players (incl. armor, offhand), clear effects. T2 teleports to the lobby, T4 clears backpacks, T5 deletes worlds (Q3).
- `/ma stop` during `END`: same exit path.

## 7. T8b part 2 – sudden death battle (plan, claude-3, 2026-11-07)
Needs: T7b (`claude-3/t7b-battle`) and T8b part 1 (`claude-1/t8b-results`) in main. Packages `dev.mobarena.arena` and tests only. `dev.mobarena.result` does not import `arena`.

### 7.1 Wiring
- `ArenaModule.init`: `ResultModule.setSuddenDeathStarter((ctx, hooks) -> ArenaPhaseListener.startSuddenDeath(ctx, BattleListener.of(hooks)))`.
- New `BattleListener.of(ResultHooks hooks)`: adapter, `finished` → `teamFinished`, `eliminated` → `teamEliminated`. `hooks` is the `ResultTracker`; in `SUDDEN_DEATH` it records into the sudden death outcomes.
- No new tick code. `ArenaPhaseListener.onTick` already ticks `ArenaBattles` in `SUDDEN_DEATH`, and `onExit(SUDDEN_DEATH)` closes it.

### 7.2 Order in the transition tick
1. `ResultModule.resolve` (own `END_SERVER_TICK` phase) gives `SuddenDeath` → `GameManager.enterSuddenDeath()`.
2. `onExit(ARENA)`: `ArenaBattles.close()` stops both battles, removes all wave mobs (team prefix), and puts players in the respawn timer back at the spawn.
3. `onEnter(SUDDEN_DEATH)`: `LobbyManager` sets survival and removes protection. Then the result listener calls `tracker.startSuddenDeath()` and the starter.
4. `startSuddenDeath`: new `ArenaBattles` (new respawn timers), one battle per team with `suddenDeath = true` (tag wave 4). **Change:** place all online team players at once (see 7.3). Do not wait for the next tick, because eliminated players are in survival in the other arena for that tick.
5. Next tick: the arena is ready → `COUNTDOWN` → the countdown titles. `onReady` places the players again (no effect).

### 7.3 Player reset (SPEC 8.1: all players alive at the team spawn)
- For each online team player: `placeAtSpawn` (own arena, survival, not invulnerable, full health and food, no fire). Also `removeAllEffects()` and `resetFallDistance()` (Q1).
- Inventory and backpack stay (keep inventory). Arena blocks are not repaired. Dropped items stay.
- Offline players: the rejoin hook for `SUDDEN_DEATH` gives the respawn timer (T7b, no change).
- Chat message to all game players at start: "Sudden death! Each team fights all enemy waves at once. The first team that kills all mobs wins."

### 7.4 Wave and time (exists in T7b, keep)
- One wave = sum of the 3 enemy waves (`plans.get(team.opponent())`). Countdown `waveCountdownSeconds`, cooldown 0, max time `suddenDeathMaxTimeSeconds`, glow after `mobGlowAfterSeconds`.
- `maxAliveMobs` still applies. Thus "all at once" spawns up to the cap, and the queue spawns the rest when mobs die (Q3).
- The time starts at the first spawn. Both arenas are ready at once and use the same countdown. Thus a time-out comes in the same tick for both teams, and the resolver compares the kills (SPEC 8.1).
- Kills: `TeamProgress.killsInCurrentWave` = all kills in sudden death (one wave).
- Move the merge into a pure helper `SuddenDeathScript.merge(List<SortedMap<String,Integer>>)` for a unit test.

### 7.5 Bug fix: dying slime at the transition (T7b)
- Fact [V, 26.3 bytecode]: `AbstractCubeMob.remove(reason)` splits if `getSize() > 1 && isDeadOrDying()`, for **all** removal reasons, also `discard()`.
- Thus `discardWaveMobs()` at the end of `ARENA` (or at an elimination) splits a dying slime. The children get the old wave tag through `MOB_CONVERSION` and stay in the sudden death arena.
- Fix in `ArenaBattle.discardWaveMobs()`: before `discard()`, `if (e instanceof AbstractCubeMob c && c.isDeadOrDying()) c.setSize(1, false);` (`setSize(int, boolean)` is public [V]).
- Safety net in `ArenaRules` `MOB_CONVERSION`: if the source has a wave tag but no running battle uses this tag, discard the new mob.

### 7.6 Edge cases
| Case | Result |
|---|---|
| A team gets 0 mobs (the enemy collected nothing) | Wave clears after the countdown → that team wins. Both 0 → same tick → draw (Q2). |
| All players of a team offline at start | `NO_PLAYERS` elimination on the first countdown tick → the other team wins. |
| All players of a team down | Eliminated at once → the other team wins (SPEC 8.1). |
| A player in the vanilla death screen at the transition | `AFTER_RESPAWN` → rejoin → respawn timer. |
| `/ma stop` in `SUDDEN_DEATH` | `onExit` closes the battles → `LOBBY`. |
| Arena missing | 60 s ready timeout → chat message and `stop()` (T7b). |
| Config changed in `ARENA` | `SUDDEN_DEATH` uses the new snapshot (GameManager sets it before `onEnter`). |
