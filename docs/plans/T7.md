## 3. BattleFlow (pure logic, the timers)
All times in ticks: `seconds * 20`, from the config snapshot at phase start (SPEC 11).
```
WAITING_ARENA --arena ready--> COUNTDOWN(1)
COUNTDOWN(n)  --countdownTicks--> FIGHT(n)            emits Countdown each 20 ticks, then SpawnWave(n)
FIGHT(n)      --spawning done && alive == 0--> n==last ? FINISHED : COOLDOWN(n)   emits WaveCleared(n)
FIGHT(n)      --fightTicks == glowAfterTicks--> (emit Glow(n), stay)
FIGHT(n)      --fightTicks >= maxWaveTicks--> ELIMINATED(TIME)
COOLDOWN(n)   --cooldownTicks--> COUNTDOWN(n+1)      (cooldown 0: go to COUNTDOWN at once)
any running   --allDown--> ELIMINATED(ALL_DOWN)
any running   --no online team player--> ELIMINATED(NO_PLAYERS)
```
```java
final class BattleFlow {
  BattleFlow(BattleScript script);
  List<BattleEvent> tick(TickInput in);       // call once per server tick
  State state(); int wave(); long elapsedTicks();
  TeamProgress progress();                    // (clearedWaves, killsInCurrentWave, elapsedTicks)
}
record TickInput(boolean arenaReady, boolean spawningDone, int alive, int killsInWave,
                 boolean allDown, boolean anyOnline) {}
```
- `elapsedTicks` starts at the first `COUNTDOWN(1)` (after the arena is ready). `Finished.ticks` = `elapsedTicks` when the last wave is cleared. Both teams have the same countdowns and cooldowns, so the times are fair.
- Empty wave: `SpawnWave(n)` spawns nothing, `alive == 0` → `WaveCleared(n)` in the same tick (SPEC 6). Then normal cooldown.
- The wave timer (`fightTicks`) starts at `SpawnWave`, not when the last mob is spawned.
- Glow fires once per wave. Children that come after the glow event also glow (`ChildTagger`).
- Elimination check order in one tick: `allDown` / `!anyOnline` first, then cleared, then time. (A team that clears the last mob and loses the last player in the same tick is eliminated. See Q6.)
- After `FINISHED` or `ELIMINATED`, `tick` returns nothing.
- `killsInCurrentWave`: deaths of mobs with the current wave tag (children too), any cause.

Side effects in `ArenaBattle` (not in `BattleFlow`):
| Event | Action |
|---|---|
| start (`ARENA.onEnter`, arena ready) | Teleport all team players to `teamSpawn` (`teleportTo(level, x,y,z, Set.of(), yaw, 0, false)` [V]). Game mode `SURVIVAL` (`setGameMode` [V]). `setHealth(getMaxHealth())` [V], `getFoodData().setFoodLevel(20)`, `setSaturation(5)` [V], `clearFire()` [V]. Inventory stays. |
| `Countdown` | Title with the number (`ClientboundSetTitleTextPacket`, `ClientboundSetTitlesAnimationPacket(0,20,5)` [V]), or the T9 helper if merged. |
| `SpawnWave` | Fill `SpawnQueue` from `SpawnPlanner`. Title `Wave n`. |
| `Glow` | `setGlowingTag(true)` [V] on all alive mobs of the wave. (Not `MobEffects.GLOWING`: milk and time do not remove the tag.) |
| `WaveCleared` | Title `Wave n cleared`. Chat: cooldown time. |
| `Finished` | `ResultHooks.teamFinished(team, ticks)`. Title `All waves cleared`. Players stay in the arena (Q3). |
| `Eliminated` | Remove all wave mobs of the team (`discard()` [V]). `ResultHooks.teamEliminated(team, progress)`. Cancel respawn timers; down players stay spectators (Q3). |

## 4. Wave spawn on the ring

### 4.1 `SpawnPlanner` (pure)
```java
record SpawnOrder(String entityId, int pointIndex, boolean water) {}
static List<SpawnOrder> plan(SortedMap<String,Integer> wave, int ringSize, int waterSize,
                             Predicate<String> isWater, long seed);
```
- Expand counts to a list (`zombie ×3` → 3 entries). Shuffle with `seed` (game seed + team + wave). Same input → same output.
- Land mobs: round robin over a shuffled ring order. Thus the mobs spread over all points, also with few mobs.
- Water mobs (`isWater`): round robin over `waterSize` water points. If `waterSize == 0`: use ring points with `water = true` (see 4.2).
- Unit tests: counts kept, spread differs by at most 1 per point, determinism.

### 4.2 `SpawnQueue` and `WaveSpawner`
- Spawn at most **10 mobs per tick** (constant `SPAWN_PER_TICK`). A wave of 300 chickens takes 30 ticks. `spawningDone` = queue empty. See Q4 (alive cap).
- Water mob = entity type in tag `EntityTypeTags.AQUATIC` [V: turtle, axolotl, guardian, elder_guardian, dolphin, squid, glow_squid, tadpole, nautilus, zombie_nautilus, + fish]. Fish never reach T7 (blacklist in T6).
- No basin (`waterSpawns` empty): place one water source at the ring point (`level.setBlock(pos, WATER)`) before the spawn (SPEC 7.3 default).
- Spawn one mob:
  1. `type.create(level, EntitySpawnReason.MOB_SUMMONED)` [V]. If null or not a `Mob`: log and skip (counts as dead).
  2. Position: point center + random offset ±1.5 (x/z). Check `level.noCollision(type.getSpawnAABB(x,y,z))` [V]. If blocked (big mob: ghast, wither, ravager, or arena damage): try the next ring points (max all points), then the point above +3, then spawn anyway at the point.
  3. `mob.finalizeSpawn(level, level.getCurrentDifficultyAt(pos), MOB_SUMMONED, null)` [V] so mobs get vanilla gear (skeleton bow, etc.).
  4. For `mob` and all `getIndirectPassengers()` [V] (spider jockey, chicken jockey): `addTag(WaveTags.tag(team, n))` [V], `setPersistenceRequired()` [V], follow range base 128 (`getAttribute(Attributes.FOLLOW_RANGE)` [V], null check).
  5. `level.tryAddFreshEntityWithPassengers(mob)` [V]. If false: count as dead, log.
  6. `WaveMobAi.engage(mob)` (section 5) for each tagged entity.
- Tag `<team>` = the **fighting** team (arena owner), not the author. Thus `mobarena.wave.red.2` = wave 2 in the RED arena (Q2).

## 5. AI: targets and anger (`WaveMobAi`)
Target = nearest team player in the arena that is alive, not spectator, online. Use `level.players()` [V] + team filter + distance. If none: no change.
- `engage(mob)` at spawn, and `retarget()` every 20 ticks for each wave mob with no valid target (null, dead, spectator, other level).

| Kind | Test | Action |
|---|---|---|
| Neutral, anger API | `mob instanceof NeutralMob` [V: wolf, bee, iron golem, enderman, zombified piglin, polar bear] | `setPersistentAngerTarget(EntityReference.of(player))` [V], `setTimeToRemainAngry(maxWaveTicks)` [V: = gameTime + ticks], `setTarget(player)`. |
| Neutral, brain | `AbstractPiglin` (piglin, brute), `Hoglin`, `Zoglin` | `getBrain().setMemoryWithExpiry(MemoryModuleType.ANGRY_AT, uuid, 600)` + `setMemory(ATTACK_TARGET, player)` [V names]. [U] memory must be registered for that mob; else it is ignored. |
| Warden | `Warden` | `increaseAngerAt(player, 150, false)` [V]. |
| Neutral, goal | `Llama` (+ trader llama), `Panda`, `Dolphin` | `setLastHurtByMob(player)` [V] + `setTarget(player)`. Their hurt-by goal attacks. [U] per type. |
| Hostile | `mob instanceof Enemy` [V] (incl. slime, ghast, phantom, shulker, wither, breeze, creaking) | `setTarget(player)`. Brain hostiles (breeze, creaking): also `ATTACK_TARGET` memory [U]. |
| Passive | all other | Nothing. They must still die (SPEC 7.3). |

- Re-anger: neutral mobs can calm down (`stopBeingAngry`, `playerDied`). `retarget()` sets anger again every 20 ticks.
- A dead player goes to spectator (section 8). Mobs drop spectator targets by themselves; `retarget()` picks the next player.
- The neutral list is "known types". Unknown neutral types get only `setTarget`. See Q5.

## 6. Wave tracking and children

### 6.1 `WaveTracker`
- `alive` = scan every 10 ticks: `level.getEntities(EntityTypeTest.forClass(LivingEntity.class), e -> e.isAlive() && e.getTags().contains(tag))` [V method]. This is the one source of truth. It sees discarded and converted mobs correctly.
- Also on `AFTER_DEATH` of a tagged mob: `kills++` and mark "rescan next tick" (fast clear after the last kill).
- `spawningDone && alive == 0` → cleared (only `BattleFlow` decides).

### 6.2 `ChildTagger` (SPEC 7.3: children get the same tag)
| Case | Event | Rule |
|---|---|---|
| Slime/magma split, zombie → drowned, skeleton → stray, hoglin → zoglin, piglin → zombified piglin (arena is an overworld-type world [U]), and all other `convertTo` | `ServerLivingEntityEvents.MOB_CONVERSION (from, to, params)` [V] | Copy all `mobarena.wave.*` tags from `from` to `to`. Copy glow. Call `engage(to)`. |
| Evoker vex, zombie reinforcement, jockeys made later, other summons | `ServerEntityEvents.ALLOW_LOAD (entity, level, reason, loadedFromDisk)` [V] | In an arena level, while a wave runs, a new `Mob` without a wave tag and with reason `MOB_SUMMONED`, `REINFORCEMENT`, `JOCKEY`, `TRIGGERED`, `BREEDING` or `CONVERSION` gets the **current** wave tag + `engage`. |
| Natural spawns | same | Reason `NATURAL`, `CHUNK_GENERATION`, `PATROL`, `EVENT`, `STRUCTURE`, `SPAWNER`, `TRIAL_SPAWNER`: return `false` (block) in arena levels. |
| Player mobs | same | Reason `SPAWN_ITEM_USE`, `DISPENSER`, `BUCKET`, `COMMAND`: allow, no tag (the mob is not a wave mob). See Q8. |
- Our own spawns use `MOB_SUMMONED` too. `WaveSpawner` adds the tag before `tryAddFreshEntityWithPassengers`, so `ChildTagger` skips them (tag present).
- `loadedFromDisk == true`: never tag (chunk reload).

## 7. Bounds (`ArenaBounds`)
- Every 20 ticks, for each alive wave mob: if `!arena.contains(mob.position())` (outside the wall, in the floor, or fell into the void): teleport to the nearest ring point (water mob: nearest water point) with `teleportTo(x, y, z)` [V], `resetFallDistance()` [V].
- Void: arena worlds are void. A mob that falls through a hole must not die by the void before the check. Check every **5 ticks** for `y < floorY - 4` (fast path). [U] `floorY` from `ArenaInstance` (add `int floorY()`).
- Players: no bounds check (barrier wall and roof). A player that falls into the void dies → section 8.

## 8. Death and respawn (`RespawnManager`, SPEC 7.5)
Active only while the team battle is running (not `FINISHED`/`ELIMINATED`) and the player is in the team arena level.
- `ServerPlayerEvents.ALLOW_DEATH (player, source, amount)` [V]. Fabric runs it at `isDeadOrDying` (2nd call) in `hurtServer`, **before** the totem check [V].
  - If the player holds a totem of undying (main or off hand): return `true` (vanilla totem saves the player).
  - Else return `false` (no vanilla death, no death screen, no drops). Then: `setHealth(getMaxHealth())`, `removeAllEffects()` [V], `clearFire()`, `setGameMode(SPECTATOR)`, broadcast the vanilla death message (`getCombatTracker().getDeathMessage()` [V]) to the team, `RespawnTimers.put(uuid, now + arenaRespawnSeconds*20)`.
  - If no other team player is alive (all are down or offline): `BattleFlow` gets `allDown = true` → eliminated (SPEC 7.5; 1-player team is the same rule).
- Every tick: for each due timer: `setGameMode(SURVIVAL)`, teleport to `teamSpawn`, full health and food, `resetFallDistance()`. Title `Respawned`. Action bar each second while down: `Respawn in n s`.
- `allDown` = no team player that is online, in the arena level, not down. Computed each tick by `ArenaBattle`.
- `LEAVE` [V]: the player counts as down (no timer). If the rest is down: eliminated.
- `JOIN` [V] during `ARENA` (T2 puts team players back to the team position; T7 handler runs after): if the battle is running: teleport to the arena, spectator, start the respawn timer (SPEC 2). If the battle is over: spectator at the team spawn.
- Respawn during countdown or cooldown is normal.
- Team players stay out of the main `ServerPlayerEvents.AFTER_RESPAWN` path. A vanilla death in the arena (for example a totem-less bypass) must not happen; if it happens anyway, `AFTER_RESPAWN` [V in TECH] teleports the player to the arena as spectator with the timer.

## 9. Sudden death API (for T8)
T8 owns the `SUDDEN_DEATH` rules (SPEC 8.1). T7 gives the runner:
```java
ArenaBattle.startSuddenDeath(TeamId team, GameContext ctx, BattleListener listener);
interface BattleListener { void finished(TeamId t, long ticks); void eliminated(TeamId t, TeamProgress p); void kill(TeamId t, int killsSoFar); }
```
- Script: 1 wave = sum of the 3 enemy waves (same `WavePlan`), countdown as normal, cooldown 0, max time `suddenDeathMaxTimeSeconds`. Tag wave number `4`: `mobarena.wave.<team>.4` (Q2).
- Arenas are not repaired; players are teleported to the spawn and filled (same start action). Mobs of the ARENA phase are already removed.
- ARENA uses a `BattleListener` that calls `ResultHooks`. T8 passes its own listener for sudden death. Thus T7 needs no T8 code.

## 10. Phase exit
`ARENA.onExit` and `SUDDEN_DEATH.onExit` (T8 calls `stop`): stop all battles, `discard()` all entities with a tag `mobarena.wave.*` in both arena levels, clear respawn timers, set down players to `SURVIVAL` at the team spawn. T5 deletes the levels at game end.
